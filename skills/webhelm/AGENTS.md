# Verified Lessons

- Imported platform helper modules do not inherit browser helpers injected into the action namespace; pass `js`, `wait_for_element`, and related helpers explicitly.
- CapCut's mode/model menus render asynchronously; wait for semantic roles such as `[role="menuitemradio"]` and `[role="listbox"][aria-label="Model"]` before reading or selecting options.
- Platform files are read live from `WEBHELM_PLATFORM_DIR`, so platform edits need no rebuild. To test unreleased CLI changes, run `WEBHELM_CLI_SOURCE=/path/to/browser-workspace WEBHELM_CLI_REFRESH=1 webhelm ...`. This selects the local CLI without changing the global Skill installation.
- DeepSeek supports visual image questions, not just OCR (live PNG check, 2026-10-29). Read final answers from `.ds-assistant-message-main-content`, not the reasoning panel. Preserve busy composers and resume pending submissions without sending again.
- Z.ai chat routes use `/c/{id}`, with `textarea[placeholder="Send a Message"]`, `#send-message-button`, and `.user-message`. Lifecycle submission actions remain unverified until explicitly exercised live.
- Keep exactly one version-controlled Chrome extension source at `skills/webhelm/extension/`. Package the Web Store ZIP from that source by converting only the manifest at build time (remove the unpacked public key, add the Web Store `update_url`). Tests, Skill distribution, and release workflows must reference that same source.
- Plain-browser fallback must not reuse pre-existing `about:blank` targets for new sessions. Sessions close their owned targets, so allocate a distinct CDP Target and clean it up if initial navigation fails. E2E must confirm all pre-existing tabs survive session stop.
\n- Z.ai response completion is a separate webpage SSE envelope (chat:completion data.done=true). Reuse one Z-specific parser for both lifecycle actions; require a durable thread URL before returning completed, and report pending instead of guessing from a submitted message.\n
- Session-level CDP isolation: one explicit CDP attachment per WebHelm Session; helpers resolve the Session context rather than the shared Browser Harness attached tab. Preserve per-session stdout/stderr and event buffering before enabling concurrent actions. Only coordinate shared tab lease management with the per-workspace lease mutex; no global browser lock.

- Unified WebHelm Node migration (2026-10-31): the deployable runtime lives **only** in `skills/webhelm/runtime/`; one Node daemon owns the CDP WebSocket, persistent JavaScript Session contexts, Helper API, extension RPC, and ChatGPT SQLite queue. No Python Browser Harness dependency or separate browser-workspace session daemon.
- A CDP Target ID and a Chrome Tab ID are different identities. For new grouped tabs, first acquire a unique extension lease identity, resolve that CDP Target, then navigate; do not match by user URL or reuse unrelated tabs. Release every owned lease, including child tabs, regardless of current target selection. Detach service-worker CDP sessions after each RPC.
- Real Chrome E2E caught bugs missed by mock tests: Node server handlers must actually respond, runtime imports must be defined, extension workers may activate asynchronously, and Browser Helpers must match the migrated platform Actions. Never promote platform status solely on mock-test success.
- The bundled Skill `package-lock.json` and Node binary are the only installation prerequisites. Keep the installer idempotent, preserve the managed Chrome profile and all user tabs, and never run concurrent old/new dispatchers against `chatgpt-new-turn.sqlite3`.
- A Chrome MV3 extension service worker can be asleep and absent from `Target.getTargets`. The browser-level `ServiceWorker.enable` method is unavailable in current Chrome CDP. Reuse an existing extension-owned page and `chrome.runtime.sendMessage` to wake its worker and receive RPC results. Do not create another profile or ungrouped tab just to activate it.
- `workspace.acquireIdentity` can race when two Node Sessions start simultaneously and reuse the same idle tab. Use a per-workspace mutex around only the extension lease+CDP-target lookup. Never restore a global lock on Session execution. Verify two simultaneous starts yield different target IDs and both releases succeed.
- ChatGPT readiness cannot assume React hydration completes at `document.readyState === "complete"`. Poll the composer for the exact harmless probe and an enabled Send button before returning true; a missing button on the first frame is not a confirmed auth failure.
- Chrome 138 / macOS Big Sur can suspend the MV3 extension worker until no CDP service-worker or extension-page target remains, even though the installed extension is enabled. Read only the known extension ID metadata in Chrome Secure Preferences to distinguish a sleeping worker from a missing extension. Wake it via a temporary task-owned extension page and `chrome.runtime.sendMessage`. Always detach and close the temporary page. If `workspace.release` fails because the group lost ownership, close only the Session's own CDP Target as a fallback; never reuse or close an unrelated tab. Home98 isolated Chrome138 E2E verified `workspace_supported:true`, one grouped lease, `recovered_tab_closes:0`, `release_error:null`.
- DeepSeek (2026-10-31): The site can create a new conversation URL and clear its input while never rendering a user message or assistant answer. URL + empty composer are NOT proof of delivery. Return unverified pending with thread identity, perform read-only resume, and never auto-resend. On resume, require a new answer after the recorded pre-submit count; an older response is not completion.
- DeepSeek SPA recovery (2026-10-31): A previous live receipt failure still had the user request and reply saved in the conversation history. The direct view was empty; clicking the SAME thread through the DeepSeek sidebar hydrated the messages. On ambiguous submission, safely reselect only the established thread (no send) and re-check source message/answer before returning pending. Preserve the previous assistant count when resuming to avoid old-answer false positives.
- DeepSeek SSE parity (2026-10-31): Node migration had lost the former passive webpage Event Stream observer and regressed to DOM-only completion. Register Page.addScriptToEvaluateOnNewDocument before navigation and passively clone the signed-in site's own completion fetch/XHR stream. Verify ready with request/response IDs, FINISHED, close, and nonempty RESPONSE text. Only use DOM as fallback; never call model API independently or auto-resubmit an uncertain request.
- DeepSeek live hotfix (2026-10-31): Node daemon refreshes top-level platform actions by mtime, but ESM static imports of shared lifecycle remain cached. To make a platform-action hotfix live without restarting the daemon and interrupting other Sessions, resolve the shared lifecycle dependency with a fresh mtime-keyed dynamic import on each invocation.

- Native Node platform Actions return both `result.value` for structured consumers and the final machine-readable `result.stdout` JSON line for existing NeoY / Relay parsers. When an Action already logs the exact JSON result, do not emit a duplicate. Relay reads workspace capacity from `webhelm capacity`, not `browser-harness` / Python REPL.
